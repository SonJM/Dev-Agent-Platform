## 범위
1. 「가져오기」에서 파일을 고르면 바로 보내지 말고 06 §3.6대로 확인 창을 띄운다: 항목 수, stdio MCP마다 이름·`command`·`args` 전체(고정폭), 경고 문구, stdio MCP가 있으면 확인 체크 전 가져오기 비활성, 취소 시 저장 없음. 기존 `bundleImport`의 결과 토스트는 유지.
2. stdio 판별은 서버가 저장할 때와 같은 기준이어야 한다. `BundleController`(와 `McpServer`)가 stdio를 어떻게 정하는지 먼저 읽고, 화면에서 같은 기준으로 판별할 수 있으면 화면만 고친다. 기준이 서버에만 있어 화면이 따라 할 수 없으면 **읽기만 하는 미리보기 API**(`POST /api/bundle/preview` — 저장하지 않고 항목 수와 stdio MCP 목록을 돌려준다, Origin 확인은 기존 상태 변경 API와 같게)를 추가하고 단위 테스트(JUnit 5, Spring 없이)를 붙인다. 어느 쪽을 골랐는지와 이유를 설명서 `## 주요 결정`에 적는다. 미리보기 API를 만들면 05 반영 필요를 `## 제안`에 적는다(PM이 반영).
3. 화면 문구에 값(경로·계정·주소)을 박지 않는다. 묶음 내용은 `textContent`로 넣는다(HTML로 해석하지 않음 — 남이 만든 파일이다).
4. 수정 뒤 `node --check`. 스크린샷 390/768/1440 3장(확인 창을 띄운 상태, stdio MCP 1개 묶음), inspect FAIL 0. 시험용 묶음 파일은 저장소 밖 임시 폴더에 두고 끝나면 지운다. 시험으로 들어간 MCP·스킬은 지운다.
5. 버전은 patch(2.0.x).
