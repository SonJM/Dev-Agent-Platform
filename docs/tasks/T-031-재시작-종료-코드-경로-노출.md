## 목적
두 가지 작은 결함을 한 patch(2.3.1)로 고친다.
1. 서버(systemd)에서 화면 「재시작」이 앱을 끄기만 하고 다시 띄우지 않는다 — 종료 코드가 10이 아니라 0으로 끝난다.
2. `/api/usage`의 구독 API 조회 실패 문구(`planError`)에 `.credentials.json` 절대 경로(사용자 홈·계정 이름)가 실려 응답과 상단바 배터리 툴팁에 보인다(OI-43, 사용자 결정 ①).

## 근거
- 요구사항: `FR-102` 인수조건 — `POST /api/system/restart`는 종료 코드 10으로 끝나고 systemd가 다시 띄운다, `/shutdown`은 0 ([01 §4](../01-requirements.md)). `FR-605`(토큰 사용량 표시)
- 결함 ① 실측(2026-11-27, 서버 2.3.0 반영 중, 메인 세션): journal 「화면 요청으로 재시작합니다」 → Hikari 종료 → `dev-agent.service: Deactivated successfully`, `ExecMainStatus=0`. 같은 jar를 개발 PC에서 `DEV_AGENT_RUN_MODE=systemd`로 띄우면 10(경합이라 환경마다 다르다)
- 결함 ① 원인(메인 세션 분석): `SystemController.exitLater`가 Tomcat 요청 스레드(데몬)에서 `new Thread(...)`로 종료 스레드를 만들어 **데몬 속성을 물려받는다**. `SpringApplication.exit(ctx, …)`가 컨텍스트를 닫아 비데몬 스레드가 모두 끝나면 JVM이 DestroyJavaVM 경로로 종료 코드 0으로 먼저 끝나 `System.exit(10)`이 늦는다
- 배포 규약: [04 §9](../04-project-structure.md#9-배포) 「Linux 기동 동작」(재시작 = 10, 종료 = 0)·「재시작 정책」·「1단계 남은 확인」 ④, [02 §4.2](../02-architecture.md) D-2
- 결함 ②: `OI-43` ([00-INDEX 미결 사항](../00-INDEX.md)) — 사용자 결정 ① 2026-11-27, [04 §8](../04-project-structure.md#8-로컬-실행) 스크린샷 가림 대상
- 테스트: `TC-028`(①), `TC-029`(②) ([07 §4](../07-test-plan.md))

## 범위
1. **종료 스레드를 비데몬으로**: `exitLater`의 종료 스레드에 `setDaemon(false)`를 명시한다. 스레드 생성 부분(이름·데몬 속성·400ms 지연 뒤 `SpringApplication.exit` → `System.exit`)을 테스트 가능하게 분리한다(예: 패키지 공개 static 메서드가 `Thread`를 만들어 돌려주고 `start()`는 호출부가 한다 — 방식은 담당 판단, 단 `System.exit`을 테스트가 실제로 부르지 않게). `restart`(10)·`shutdown`(0) 둘 다 같은 경로를 탄다.
2. **TC-028 단위 테스트**: 데몬 스레드 안에서 종료 스레드를 만들어도 `isDaemon() == false`이고 이름이 `system-exit`인지 확인한다. 재시작·종료가 각각 10·0을 넘기는지도 확인할 수 있으면 함께(종료 코드를 정하는 부분이 분리돼 있을 때).
3. **`planError`에서 경로 빼기**: 응답에 싣는 문구에 로컬 절대 경로가 들어가지 않게 한다. 인증 파일 단계(없음·읽기 실패·JSON 해석 실패)의 실패는 예외 메시지를 싣지 말고 고정 표기(`~/.claude/.credentials.json` 또는 "인증 파일")와 원인 종류만 싣는다(예: `인증 파일(~/.claude/.credentials.json) 없음`, `… 읽기 실패`, `… 형식 오류`). accessToken 없음·`HTTP <코드>`는 지금 문구 그대로 둔다. 그 밖의 예외는 클래스 이름만(메시지 생략)으로 둔다 — 메시지에 경로·내용이 섞일 수 있다. 문구를 만드는 부분은 순수 함수로 분리한다(예: `static String planErrorText(Exception)`). 429 판별(재시도 5분)은 지금처럼 동작해야 한다(문구를 바꾸며 깨지지 않게 — 원래 예외 기준으로 판별). `log.debug`의 상세(경로 포함)는 로컬 로그라 남겨도 된다.
4. **TC-029 단위 테스트**(`UsageServiceTest`에 추가, 기존 테스트는 고치지 않는다): `NoSuchFileException`(절대 경로 메시지)·`AccessDeniedException`·JSON 해석 예외·accessToken 없음·`HTTP 401`·`HTTP 429`·기타 예외(메시지에 경로 포함)를 넣어 결과 문구에 `user.home` 값과 넣은 절대 경로가 없고, 고정 표기·`HTTP 401` 등 원인 구분이 남는지 확인한다.
5. **버전** `build.gradle` `2.3.0` → `2.3.1`(patch — 버그 수정).
