## 목적
서버에서 앱(과 앱이 띄우는 검증 빌드·수정 세션)이 항상 JDK 21로 돈다는 것이 unit 틀과 절차서에 드러나고, 저장소에서 빌드·테스트가 JDK 21로도 통과함이 확인된다. 서버 기동 확인 스크립트에 남은 프리뷰 흔적이 없다.

## 근거
- 결정: `OI-29` ① (2026-11-25, 사용자 — 서버 unit `JAVA_HOME`을 JDK 21로 고정, 앱도 21에서 실행, 코드 변경 없음), `OI-31` ① ([00-INDEX](../00-INDEX.md))
- 구조: [04 §9](../04-project-structure.md) 실행 런타임·unit 환경
- 원본: [T-009 변경 설명서](./results/T-009-windows-요소-제거.md) 보고 사항, java-reviewer MEDIUM
- 테스트: `TC-001` ([07 §4](../07-test-plan.md))

## 관련 코드 경로
- `deploy/systemd/dev-agent.service` — 6행 주석 `<JAVA_HOME> JDK 17+` 및 `JAVA_HOME`·`PATH`·`ExecStart` 자리
- `deploy/README.md` — 자리표시자 표(13행), JDK 경로 확인 절차(31행 근처), unit 핵심 설명(120행 근처)
- `deploy/smoke/server-smoke.sh` 142행 — `PREVIEW_ENABLED=false`
- 읽기만: `build.gradle`(toolchain 17)

## 범위
1. unit 틀 주석과 README의 `<JAVA_HOME>` 설명을 "JDK **21** 설치 경로"로 바꾸고, 이유 한 줄(검증 빌드·수정 세션이 봇 JVM의 JDK와 PATH 도구를 쓰므로 대상 프로젝트가 요구하는 가장 높은 JDK에 맞춘다)을 README에 둔다. 서버의 java가 21인지 확인하는 명령(`<JAVA_HOME>/bin/java -version`)을 절차에 넣는다. 값(실제 경로)은 쓰지 않는다 — 자리표시자 그대로.
2. `server-smoke.sh`의 `PREVIEW_ENABLED=false` 한 줄(같은 줄의 다른 변수는 유지)을 지운다. 이 스크립트가 쓰는 java가 JDK 21인지 출력에 남기는 것이 한 줄로 되면 넣는다(안 되면 설명서에 사유).
3. 개발 PC에서 Gradle을 **JDK 21로** 띄워 `test bootJar`가 통과하는지 확인한다(toolchain 17은 바꾸지 않는다 — 컴파일은 17, 데몬·테스트 실행 JDK만 21). JDK 21 경로를 찾지 못하면 실행하지 말고 설명서에 "미실행 — JDK 21 없음". 실행한 JDK 버전은 `java -version` 첫 줄만 적는다(경로는 `~`/`<repo>`/`<tmp>`로 가린다 — 07 §9).
4. 런타임 21은 이미 확인됨(T-009 qa 확인의 앱 로그가 Java 21) — 앱을 따로 띄우지 않는다.
