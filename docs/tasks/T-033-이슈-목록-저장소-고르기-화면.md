## 목적
에이전트 탭 「이슈 목록」 창에서 내 GitHub 저장소를 고르면 그 저장소의 열린 이슈가 바로 나오고, 골라 시작할 수 있게 한다. 대상이 아닌 저장소는 확인을 받고 시작하면 대상(★)이 된다. 플랫폼 탭을 들르지 않아도 된다.

## 근거
- 화면: `S-02` [06 §3.3](../06-functional-specification.md) 「내 저장소에서 바로 고르기」 — 왼쪽·오른쪽 칸 구성, 업무 규칙 ①~⑨, 오류·빈 상태, **모바일 동작 (390px)** 「이슈 목록」 창
- API: [05 §2.3](../05-api-specification.md) `GET /api/issues-repos`(형식 그대로), `GET /api/issues-projects`, `GET /api/issues-list`(2.4.0 — `target`·`archived`·`blocked`), `POST /api/issues-start`(→ `{ ok, result, added, ref }`). 실제 형식은 [T-032 변경 설명서](./results/T-032-내-저장소-이슈-시작-api.md)를 따른다(다르면 보고)

## 범위
1. `#ilDlg`를 06 §3.3대로 두 칸(왼쪽 「저장소」 필터·새로고침·★ 대상 먼저 / 오른쪽 「이슈 (<repo>)」 상태 한 줄·이슈 행)으로 바꾼다. 창 밖(사이드바·스테퍼·세션 목록) 배치는 건드리지 않는다.
2. 업무 규칙 ①~⑨: 창을 열 때만 두 조회(`Promise.allSettled`), 저장소를 고를 때만 이슈 조회, 폴링·`UI.every` 없음. 처음 고르는 저장소 순서(localStorage 키 이름은 설명서에), 대상 아닌 저장소 시작 `confirm`(라벨 이슈 수 = 지금 목록의 `labels`에 응답 `label`이 있는 수), 결과 처리(`added`면 `projects` 다시 읽기 → ★·사이드바 프로젝트 필터 갱신, 이슈·세션 목록 다시 읽기), `blocked`·보관·꺼짐·조회 실패 처리, 대상 0개여도 창이 열림(기존 「대상 프로젝트가 없습니다」 토스트 제거).
3. 시작·다시 시작은 `POST /api/issues-start`(form `project`, `number`)로. 응답은 HTTP 상태와 `ok`를 둘 다 본다(실패면 `err` 토스트, ★ 달지 않음). 다른 화면의 `/api/issues-command` 사용(「가져오기」=스캔 등)은 그대로.
4. 출력: 서버 문자열은 전부 `esc`/`textContent`, `webUrl`은 `https://github.com/`으로 시작할 때만 링크, `onclick` 속성에 서버 문자열을 넣지 않는다(색인·data 속성으로).
5. 모바일(390px) 두 단계 이동(저장소 → 이슈, 「← 저장소」), 768px 이상 두 칸 — 06 §3.3 모바일 동작 그대로.
6. 스크린샷용 상태는 Playwright `page.route`로 `/api/issues-repos`·`/api/issues-list`·`/api/issues-start`를 흉내 내도 된다(QA 환경에 토큰 없음). 실제 대상 목록을 바꾸는 요청은 보내지 않는다.
