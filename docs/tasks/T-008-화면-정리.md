## 범위

### 탭 구성 — 다섯 탭 유지
메신저 탭(S-04)은 **없애지 않는다**. Phase 4에서 Telegram 상태가 이 화면에 들어온다(탭 흡수 여부는 SPA 기획 OI-13). `ui.js`의 탭 목록·`Alt+4`·`PAGE_NAMES`는 그대로 둔다.

### S-01 홈 (`home.html`)
- 「메신저」 카드(`#homeMessenger`, 수집·요약·멘션 통계)와 그 그리기 코드를 지운다. `loadHome`의 `/api/status` 호출도 지운다(이 카드만 쓴다).
- KPI 「연동」의 보조 문구 `메신저 · LLM · 지식` → `메신저 · 코딩 에이전트`.
- 「연동 상태」 카드·사용량 카드는 그대로 둔다(사용량 출처 라벨의 `chat`·`ops`는 과거 기록 표시용이라 남긴다).

### S-04 메신저 (`messenger.html`)
- 지운다: 상단 통계 줄(`#stats` — 수집 메시지·요약·멘션 처리·수집 모드·멘션 모드·LLM 헬스체크), 「방 설정」 카드 전체, 「최근 활동」 카드 전체.
- 남긴다: 「메신저 알림」 카드(현행 `loadNotify`). 안내 문구의 "@AI 명령의 답" → "메신저에서 직접 보낸 명령의 답".
- 새로 넣는다(기존 카드·`callout`·`badge` 스타일만 사용)
  - **연결 상태 카드**: `GET /api/platform`의 `ports`에서 `port === 'messenger'`인 항목의 상태 배지·구현체(`provider`)·요약(`summary`)을 보여 준다. `provider`가 `none`이면 "메신저 없이 사용 중 — 알림은 알림함에 남습니다"와 설정 방법(`.env`의 `PLATFORM_MESSENGER` 키 이름, 값은 적지 않는다)을 안내한다. 토큰·대화 id 같은 값은 표시하지 않는다. 20초 주기는 `UI.every`.
  - **명령 안내 카드**: [06 §4.2](../06-functional-specification.md) 표의 입력과 동작을 정적 문구로 적는다(`운영 …`·방 요약·일반 대화는 넣지 않는다). 저장소 표기는 Phase 3 전이므로 현행 `group/repo#12`.
- 페이지 제목·상단바 이름은 「메신저」 그대로.

### S-05 플랫폼 (`platform.html`)
- 지운다: 「사내 문서 (RAG)」 카드 전체, MCP 카드 안의 내장 운영 MCP 상태 목록(`#mcpServers`·`#mcpSummary`)·질의 입력(`#mcpQ`·`#mcpAskBtn`·`#mcpAnswer`)·`@AI 운영` 안내 문구, 「로컬 프리뷰」 항목(`#previewStat`).
- MCP 카드 제목 「운영 MCP」 → 「MCP 서버」. 사용자 정의 MCP 서버 목록·등록·수정·삭제 폼은 **동작을 바꾸지 않는다**(FR-208, 가정 AS-07).
- 「시스템」 카드의 홈 경로·설정 파일 경로 표시는 **그대로 둔다**(OI-23 결정 — 보는 사람이 주인뿐이고 `.env` 위치를 찾는 데 쓰인다).
- 「연동」 카드는 화면 코드를 고치지 않는다(아래 "서버 응답을 그대로 그리는 곳").

### S-02 에이전트 (`agent.html`)
- 프리뷰 스크린샷 갤러리를 지운다: `#shots` 요소, `.shots`·갤러리 전용 스타일, `loadShots`와 `shotsLoadedFor`, 이벤트 로그에서 "스크린샷|프리뷰" 문구로 `loadShots`를 부르는 분기, `/api/agent/sessions/{id}/shots` 호출, 「프리뷰 열기」 링크. 그 밖의 탭(설계안·변경 요약·검증·Diff·로그)은 건드리지 않는다.

### 공통 스크립트·스타일 (`admin.js`, `admin.css`)
- 지운 화면만 쓰던 함수와 전역을 지운다: `loadStatus`·`llmTest`·`ROOMS`·`loadRooms`·`syncRoomsFromDom`·`renderRooms`·`save`·`loadRecent`와 `[data-r]` 탭 처리·`loadDocs`·`isStale`·`refreshDocs`·`searchDocs`·`loadMcp`·`loadPreview`·`mcpAsk`와 관련 `on(...)` 등록, 아이콘 주입 목록에서 없어진 id. `bundleImport` 끝의 `loadMcp()` 호출도 뺀다.
- `stat()` 같은 도우미와 `admin.css`의 스타일은 **남은 화면에서 쓰는지 검색한 뒤** 안 쓰는 것만 지운다(예: 홈의 리서치 목록도 `.rrow`를 쓴다). 지운 것과 남긴 것을 변경 설명서에 적는다.
- `admin.js` 최상위에서 요소에 이벤트를 걸 때는 `on(id, ev, fn)`(없는 요소에서 예외가 나면 화면 전체가 멈춘다).

### 서버 응답을 그대로 그리는 곳 — 화면에서 거르지 않는다
「연동」 카드의 행(홈·플랫폼)과 「메신저 알림」의 유형 목록은 서버가 준 목록을 그대로 그린다. 채팅 모델·도구 채팅 모델·지식 검색 행과 `summary`·`mention` 유형은 **T-007이 서버 응답에서 빼면 사라진다**. 화면에 임시 걸러내기 코드를 넣지 않는다(T-007은 화면 파일을 고치지 않으므로 지울 사람이 없다). 이 두 곳의 확인은 T-007의 qa 확인에서 한다.

### e2e
- `e2e/core/shell-tabs.spec.ts`의 `TABS`에서 메신저 항목의 `marker`가 지워지는 「방 설정」이다. **이 문자열 하나만** `'메신저 알림'`으로 바꾼다(그대로 두면 TC-006이 의도된 변경 때문에 실패한다). 그 밖의 e2e 파일은 고치지 않는다 — `TC-013` 자동화(`e2e/tasks/T-008.spec.ts`)와 핵심 묶음 실행은 qa 확인이 한다.

### 스크린샷 (공개 저장소 — 계정명·로컬 경로가 찍히면 안 된다)
- 8778 QA 인스턴스에서 홈·메신저·플랫폼을 390 / 768 / 1440px로 찍는다(화면당 3장).
- 플랫폼 「시스템」 카드는 작업 디렉터리 절대경로(계정명 포함)를 보여 준다. **찍기 전에 로컬 경로를 `~`로 가린다** — `e2e/support/shot.ts`의 `maskLocalPaths`와 같은 방식(텍스트와 `title` 속성 모두). 가리지 않은 스크린샷은 저장소에 두지 않는다.
- 8778은 한 번에 한 실행만 쓴다. 띄우기 전에 8778이 비어 있는지 보고, 캡처가 끝나면 `bash e2e/scripts/stop-app.sh`로 반드시 내린다(04 §8). 사용자 인스턴스(8777)는 건드리지 않는다.
