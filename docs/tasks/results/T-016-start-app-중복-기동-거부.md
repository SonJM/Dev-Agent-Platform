# T-016 변경 설명서 — start-app.sh 중복 기동 거부

> 담당: qa (qa) · 2026-11-24 · 지시서: [T-016](../T-016-start-app-중복-기동-거부.md)

## 요약
QA 인스턴스(8778)가 이미 리슨 중이면 `start-app.sh`가 내장 DB 데이터 디렉터리를 지우기 전에 거부하고 종료한다.
T-006 2차 재작업에서 떠 있는 인스턴스의 `pgdata-embedded`가 지워진 사고의 재발 방지다.
리슨 여부(TCP 연결)로 판정하므로 응답 없는 인스턴스도 거부한다.

## 그림
그림 없음 — 스크립트에 조건 분기 하나를 더한 작은 변경이다. 흐름은 "8778 TCP 연결 성공 → 안내 한 줄 출력, 종료 코드 3 / 실패 → 기존대로 DB 초기화 후 기동"이다.

## 파일 지도
| 파일 | 추가/수정 | 역할 (한 줄) |
|---|---|---|
| `e2e/scripts/start-app.sh` | 수정 | `PORT` 변수 도입, `rm -rf pgdata-embedded` 앞에서 `/dev/tcp` 연결 검사(2초 제한) 후 거부 |

## 주요 결정
| 결정 | 이유 | 검토한 대안 |

| 종료 코드 3 | 기존 코드(jar 없음 2)와 구분 | 1 |
| 포트는 `PORT` 변수 한 곳, `ADMIN_PORT`도 같은 변수 | 범위 규정(한 곳에서 사용) | — |

## 제안
- 04 §8에 "start-app.sh는 8778이 사용 중이면 거부한다(먼저 stop-app.sh)" 한 줄 추가를 PM 검수 때 검토.
- 실행 중 관찰: 이전 실행이 남긴 내장 PostgreSQL이 잠시 살아 있으면 `rm -rf pgdata-embedded`가 "Directory not empty"로 실패해 기동이 중단된 적이 있다(이번 작업 중 1회, 재현 조건 미확정). 범위 밖이라 손대지 않았다.

## 검증
- 검증 명령: 지시서 검증 명령 → `bash -n` 통과. 8778 비어 있을 때 첫 기동 status 200. 떠 있는 채 재호출 시 `port 8778 in use — run stop-app.sh first`, 종료 코드 3, `pgdata-embedded` 항목 수 25 → 25(지워지지 않음), 기존 인스턴스 status 200 유지. `stop-app.sh` 종료 코드 0, 이후 8778·54329 리슨 0.
- 추가 확인: 연결만 받고 응답하지 않는 리스너를 8778에 둔 상태에서도 거부(종료 코드 3).
- 테스트: 별도 테스트 코드 없음(셸 스크립트, 위 수동 시나리오).
