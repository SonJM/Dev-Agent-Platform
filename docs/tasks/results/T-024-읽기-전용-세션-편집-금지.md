## 요약
- OI-34 ①: `FIX` 단계가 아니고 플랫폼 관리 세션도 아닌 모든 세션(ANALYZE·VERIFY)은 `Edit`·`Write`·`MultiEdit`·`NotebookEdit`를 쓸 수 없다.
- OI-33 ①: 관리 세션의 curl 금지 경로에 `api/mcp-servers`·`api/agent-subagents`·`api/agent-teams`·`api/agent-models`·`api/issues-projects`를 더했다.
- 두 변경 모두 `ClaudeCliAgent.disallowedTools` 한 곳이다. 테스트 이름 `tc023*`는 `t023*`로 바꿨고 버전은 2.0.3.

## 그림
그림 없음 — 금지 목록 조립 조건 한 줄과 상수 목록 추가라서 흐름 그림 대상이 없다. 조건은 아래 표로 대신한다.

| 세션 | stage | maintain | 편집 도구 | curl |
|---|---|---|---|---|
| 이슈 분석·설계 수정·변경 요약, 리서치 작성·검증자·수정 | ANALYZE | 아니오 | 금지 | 전부 금지 |
| 검증 리뷰어 | VERIFY | 아니오 | 금지 | 전부 금지 |
| 이슈 수정 | FIX | 아니오 | 허용 | 전부 금지 |
| 플랫폼 관리 | FIX | 예 | 허용 | 상태 변경·설정 API 경로만 금지 |

## 남는 위험
- Bash로 파일을 쓰는 우회(`echo >`, 스크립트 언어)는 막지 못한다. 프롬프트 금지에 의존한다.
- 관리 세션 금지는 부분 문자열 비교라 `//`·`/./`·문자열 조합으로 우회할 수 있다. 실질 차단은 요청 토큰(OI-22 ②) 몫이다.
- 금지 목록 밖 POST(예: 다른 설정 API)는 관리 세션에서 여전히 curl로 호출할 수 있다(OI-33 ②).
