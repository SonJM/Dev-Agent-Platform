## 목적
앱이 띄우는 자식 프로세스(Claude CLI 세션, 대상 저장소의 검증 빌드, git, 플랫폼 관리의 git)가 앱의 비밀 환경변수(DB 접속값, 저장소·메신저 토큰)를 물려받지 않는다. 대상 프로젝트의 테스트가 같은 이름의 변수(예 `DB_URL`)로 이 플랫폼의 DB에 붙는 일, 에이전트 세션이 `env`로 값을 보는 일, 빌드 로그에 값이 남는 일을 막는다.

- 설정 키: `application.yml`의 `${…}` 자리표시자 중 비밀값 — 현재 `DB_URL`·`DB_USERNAME`·`DB_PASSWORD`, `GITLAB_TOKEN`. 메신저 어댑터 토큰 등 앞으로 생길 비밀 키도 같은 목록에 더할 수 있게 한다

## 범위
1. 공통 함수 하나를 만들고 위 생성처 전부가 `start()` 전에 그것을 거친다. 제거 목록은 **설정 키 이름 상수 한 곳**(코드에 흩어 쓰지 않는다). 이름 규칙(예 `*_TOKEN`·`*_PASSWORD`·`*_SECRET`)을 더 넣을지는 판단해 근거를 설명서에 적는다 — 넣는다면 아래 3의 예외가 지워지지 않게.
2. 앱이 **일부러 넣는** 값은 지운 뒤에 넣는다(순서가 지켜져야 한다):
   - `GitRunner`의 `GIT_CONFIG_*`(토큰으로 만든 인증 헤더) — git에만 필요하므로 유지
   - `ClaudeCliAgent`의 `mcp.env()`(사용자 정의 MCP 서버의 `${ENV}` 비밀값을 자식 env로만 넘기는 설계 — `CLAUDE.md` "사용자 정의 MCP 서버") — 유지. 사용자가 MCP 헤더에 `DB_PASSWORD` 같은 앱 비밀 키를 참조했다면 어떻게 되는지 설명서에 적는다(지우는 쪽이 기본)
3. 단위 테스트(JUnit 5, Spring 없이): 제거 목록의 키가 모두 사라짐, 목록 밖 일반 변수(`PATH`·`HOME`·`JAVA_HOME` 등)는 남음, 2의 값은 지운 뒤 넣으면 남음. 생성처가 공통 함수를 거치는지는 테스트 또는 검증 명령의 검색으로 지킨다.
4. `CLAUDE.md` 코드 작업 규칙에 한 줄: "자식 프로세스는 공통 함수로 환경을 정리한 뒤 띄운다". 버전은 patch(2.0.x) — 사용자에게 보이는 기능 변화 없음.
