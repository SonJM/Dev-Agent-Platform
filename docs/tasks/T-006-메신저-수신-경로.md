## 범위
- `MessengerPort`에 "자기 대화의 새 메시지(사용자가 보낸 것만, 시간순)와 다음 커서" 수신 규약을 더한다. 커서는 코어가 `bot_setting`의 `messenger_cursor`([03 §2](../03-data-model.md))에 저장한다. `none` 구현체는 빈 결과.
  - 규약은 **Telegram long polling에 맞춘다**(첫 실제 구현체가 T-013 Telegram — 앞서 확정). 즉 어댑터가 제한 시간 동안 기다렸다 돌려주는 차단형 호출을 허용하고(Telegram `getUpdates`의 `offset`·`timeout`), 커서는 어댑터가 정하는 문자열(코어는 해석하지 않고 저장·전달만)이다. 다른 메신저용 일반화는 하지 않는다.
- 명령 라우터: 06 §4.2의 표대로 분기. 답변 해석은 `IssueTexts`의 기존 함수를 쓴다. `@AI` 키워드 처리를 없앤다.
  - 라우터는 `llm/ChatModel`·`llm/ToolChatModel`과 `mcp/`(운영 MCP)를 **참조하지 않는다**. 06 §4.2의 "제거되는 명령"(`운영 …`, 일반 대화 응답)은 옮기지 않고, 알 수 없는 글은 명령 안내 1회로 답한다(TC-011). 포트·운영 MCP 자체의 삭제는 T-007이다(채팅 모델 포트·운영 MCP·`운영` 질의 제거 — D-7·D-11, 앞서 확정).
  - 자기 대화로 보내는 답·안내는 사용자가 보낸 명령의 답이면 `sendToSelf`, 플랫폼이 스스로 보내는 알림이면 `notifySelf(kind, …)`(알림 유형 끄기 준수 — `CLAUDE.md` 알림함 절, TC-011).
- `IssueAgentService`의 답변 소비를 `chat_message` 조회에서 "라우터가 전달"로 바꾸고 `wait_after_seq`를 없앤다. 대시보드 입력 경로는 그대로.
- 수신 대기는 `@Scheduled` 스레드를 잡지 않는다.
- 이 작업이 끝난 시점에 `collect/`·`mention/`은 아직 남아 있어도 된다. 다만 명령·답변 처리가 **두 경로에서 중복 실행되지 않게** 옛 경로의 명령·답변 분기는 끊는다.
