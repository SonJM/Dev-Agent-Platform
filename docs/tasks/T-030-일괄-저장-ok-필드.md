## 목적
일괄 저장이 통째로 거부돼도(요청 100개 초과·상한 50 초과) 응답 모양이 정상 처리와 같아 화면이 성공으로 보이던 문제를 없앤다. 응답에 `ok`를 더해 화면(T-029)이 구분하게 한다.

## 근거
- API: [05 §2.3](../05-api-specification.md) `POST /api/issues-projects/set` — 응답 `{ ok, result, added, removed, rejected }`
- 화면 규칙: [06 §3.6](../06-functional-specification.md) 저장소 고르기 ⑩
- 테스트: `TC-026` ③·⑥의 `ok` 기대 ([07 §4](../07-test-plan.md))
- 발견: T-029 typescript-reviewer MEDIUM(검수 2026-11-27)
- 요구사항: `FR-301`

## 관련 코드 경로
- 수정: `src/main/java/io/github/lib0823/devagent/issue/IssueProjects.java`(`setProjects` 241~290행 근처, `setResult` 374행)
- 테스트: `src/test/java/io/github/lib0823/devagent/issue/RepoPickerTest.java`

## 범위
1. `setResult`에 `ok`를 넣는다(맵 첫 항목). 요청 100개 초과(`MAX_REQUEST_PATHS`)와 유효 항목 상한 초과(`MAX_PROJECTS`)로 아무것도 저장하지 않은 두 경로는 `false`, 그 밖(일부 `rejected`, 변경 없음 포함)은 `true`.
2. `RepoPickerTest`에 두 거부 경로의 `ok=false`, 정상·일부 거부 경로의 `ok=true` 확인을 더한다(기존 테스트를 고치지 말고 추가).
3. 버전은 그대로(2.3.0 묶음, 미커밋).

## 범위 밖
- 화면(`static/`) — T-029 재작업이 한다
- `mergeProjects`·`/add`·`/remove` 응답 형식, HTTP 상태 코드 변경
