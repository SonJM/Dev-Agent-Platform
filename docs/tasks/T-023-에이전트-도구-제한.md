## 범위
1. **검증 리뷰어(VERIFY)**: `--disallowedTools`에 `Edit`, `Write`, `MultiEdit`, `NotebookEdit`를 더한다. `stageNote`의 수정 금지 문장은 그대로 둔다(Bash로 쓰는 경로는 도구 금지로 못 막음 — 설명서에 남는 위험으로).
2. **이슈(분석·수정)·리서치·검증 세션**(플랫폼 관리가 아닌 모든 세션): `--disallowedTools`에 `Bash(curl:*)`, `Bash(wget:*)`를 더한다. 금지가 허용보다 우선하므로 사용자가 `.env`로 도구 목록에 curl을 넣어도 막힌다 — 이 동작 변화를 `CLAUDE.md`·`README.md`의 해당 설정 설명에 한 줄로 적는다.
3. **플랫폼 관리 세션**: 위 상태 변경 경로가 든 curl을 금지 패턴으로 막는다(예: `Bash(curl *maintain*)`, `Bash(curl *system/restart*)` …). 먼저 설치된 Claude Code의 권한 규칙이 **패턴 중간의 `*`**를 지원하는지 공식 문서(또는 `claude --help`·설정 문서)로 확인하고 근거를 설명서에 적는다. 지원하지 않거나 확인할 수 없으면 3은 하지 말고 1·2만 끝낸 뒤 설명서 `## 제안`에 보고한다(PM이 OI로 다시 연다). 상태 조회 GET과 스킬 등록·삭제는 막히지 않아야 한다.
4. 금지 목록 조립은 단계·출처별로 한 곳(메서드 하나)에서 하고, 단위 테스트(JUnit 5, Spring 없이)로 지킨다: VERIFY에 편집 도구 4개, 플랫폼 관리가 아닌 세션에 curl·wget, 플랫폼 관리 세션에는 curl 전체 금지가 **없고** 3의 패턴이 있음(3을 했다면), 기존 항목(`PowerShell`, 플랫폼 관리의 `Bash(git push:*)`·`Read(./.env)`, 서브·팀 토글)이 유지됨.
5. 버전은 patch(2.0.x).
6. **`.env` 읽기 금지(T-021 보안 리뷰 MEDIUM-1, 2026-11-25 메인 세션 편입)**: T-021은 환경변수 상속만 막았고, 자식 세션은 같은 OS 계정이라 작업 디렉터리·앱 홈의 `.env`를 직접 읽을 수 있다. **모든 세션**(이슈 분석·수정, 리서치, 검증, 플랫폼 관리)의 `--disallowedTools`에 `.env` 읽기 금지를 넣는다 — Read 도구 패턴(현재 플랫폼 관리의 `Read(./.env)`를 앱 홈·하위 경로까지 덮는 형태로 넓혀 전 세션에), Bash의 파일 출력 명령 패턴(`cat`·`head`·`tail`·`less`·`grep` 등 + `.env`), Grep·Glob 도구가 `.env`를 대상으로 하는 경우. Read/Bash 패턴의 경로·중간 `*` 문법은 3과 같은 확인 근거를 쓰고, 지원되지 않는 형태는 하지 말고 설명서 `## 제안`에 보고한다. `.env.example`·`env.template` 읽기는 막히지 않아야 한다(대상 저장소의 `.env.example`도). 4의 단위 테스트에 전 세션의 `.env` 패턴 존재를 더한다. 남는 위험(스크립트 언어·다른 명령으로 우회, 개발 PC 내장 DB의 127.0.0.1 trust 인증)은 설명서에 남는 위험으로만 적는다.
