## 관련 코드 경로
- 개명: 패키지 `gitlab/` → `issue/`(테스트 패키지 포함), `config/GitLabProperties` → `IssueProperties`, 설정 `gitlab.*` → `issue.*`, 환경변수 `GITLAB_*` → `ISSUE_*`, `bot_setting` 키 `gitlab_projects` → `projects`, `issue_session` 컬럼(`issue_iid` → `issue_number`, `mr_url` → `pr_url`, `project_id`·`work_id` 삭제), `issue_event.kind` 값 `GITLAB` → `REMOTE`, 남은 `bot.*` 설정 → `platform.*`
- 함께: `db/schema.sql`·매퍼 `ensureTable()`, `application.yml`, `.env.example`, `env.template`, `deploy/env.server.example`, `README.md`, `CLAUDE.md`

## 범위
- 위 개명 전부와 그에 따른 참조 수정. 로직은 바꾸지 않는다.
- 확정한 설정 키·환경변수 이름 대응표(옛 이름 → 새 이름)를 변경 설명서에 적는다(사용자가 서버 `.env`를 고칠 때 쓴다).

- T-010 이후 상태 반영(2026-11-26 PM):
  - `github.*`(`config/GitHubProperties`, `GITHUB_*`)는 그대로 둔다 — 호스팅 이름이 남는 유일한 곳.
  - `gitlab.create-mr`(`GITLAB_CREATE_MR`)처럼 MR이 든 키는 PR로(대응표에 적는다). `GITLAB_WORK_DIR`·`GITLAB_ENABLED`·`GITLAB_PROJECTS`도 대응표 필수(사용자가 서버 `.env`를 고친다).
  - 설치 점검(`ops/Doctor`·`GitHubCheck`)의 힌트 문구에 나오는 옛 환경변수 이름도 새 이름으로(T-010 qa 제안 — 화면에 `GITLAB_WORK_DIR`가 보임).
  - `ChildEnv.SECRET_KEYS`의 `GITLAB_TOKEN`은 옛 `.env` 잔존값 차단용이라 남겨도 된다 — 남기면 변경 설명서의 "의도적으로 남긴 곳"에 적는다.
  - `OI-36` 결정 ②(2026-11-26)로 `issue_session`에 새 컬럼을 넣지 않는다.
- **커밋은 T-012와 한 묶음**: T-011만 커밋하면 화면이 옛 응답 필드(`issueIid`·`mrUrl`)를 읽어 깨진다. PM 검수 뒤 T-012를 이어서 진행하고, T-012 qa 확인이 끝난 뒤 두 작업을 함께 커밋한다(메인 세션).
- 버전: `build.gradle`은 올리지 않는다 — 커밋 때 메인 세션이 `OI-39` 결정대로 정한다.
