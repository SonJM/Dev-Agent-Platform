## 범위
1. **편집 도구 금지 확대(OI-34)**: `EDIT_TOOLS`(`Edit`·`Write`·`MultiEdit`·`NotebookEdit`) 금지 조건을 "VERIFY"에서 "**FIX 단계가 아니고 플랫폼 관리 세션도 아님**"으로 바꾼다(ANALYZE·VERIFY 전부 — 이슈 분석·설계 수정·변경 요약, 리서치 작성·검증자·수정 포함). 착수 때 위 읽기 전용 호출처를 다시 검색해 `Stage.ANALYZE`/`VERIFY`로 도는 세션 중 **파일을 써야 하는 것이 없음**을 확인하고 설명서에 표(호출처·단계·쓰기 필요 여부)로 남긴다. 쓰기가 필요한 세션이 있으면 그 세션을 막지 말고 `## 제안`에 보고한다.
2. **관리 세션 금지 경로 추가(OI-33)**: `MAINTAIN_DENIED_APIS`에 `api/mcp-servers`, `api/agent-subagents`, `api/agent-teams`, `api/agent-models`, `api/issues-projects`를 더한다(부분 문자열이라 `/delete`·`/add`·`/remove` 하위 경로와 GET 조회도 함께 막힌다 — `api/maintain` 선례와 같다). `MaintainPrompts`의 상태 조회 안내 GET(`/api/system/status`·`doctor`·`issues`·`research`·`platform`·`skills`)과 스킬 등록·삭제는 막히지 않아야 한다. 주석에 남는 위험(부분 문자열 우회, 목록 밖 POST)이 이미 있으면 새 경로가 왜 들어갔는지 한 줄만 더한다.
3. **테스트**: 기존 `tc023*` 테스트 이름을 `t023*`로 바꾼다(TC-023과 혼동 — T-023 검수 메모, 내용은 그대로). 새 테스트(`t024*`, JUnit 5, Spring 없이): ANALYZE(비관리)에 편집 도구 4개, FIX(비관리)에는 없음, 관리 세션(FIX + maintain)에는 없음, VERIFY는 그대로, 관리 세션에 새 5개 경로 패턴이 있고 `api/skills`·`api/system/status` 패턴은 없음.
4. 버전은 patch(2.0.x).
