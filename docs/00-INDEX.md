## 핵심 전제

문서 전체가 아래 전제 위에 서 있다. 흔들리면 설계 전반을 재검토한다.

1. **사용자는 한 명이다.** 계정·역할·다중 사용자 기능을 만들지 않는다. → [01 §1.2](./01-requirements.md#12-목적)
2. **앱은 루프백에만 바인드한다.** 외부로 여는 일은 Tailscale이 맡는다. 앱이 `0.0.0.0`이나 공인 주소에 직접 바인드하는 설정을 만들지 않는다. → [02 §4.2 D-1](./02-architecture.md#d-1-접근-제어-루프백-바인드--tailscale-serve)
3. **하위 호환을 지키지 않는다.** 설정 키·DB 스키마·실행 방식이 바뀌어도 된다. 대신 쓰지 않는 것은 남기지 않는다(KISS/YAGNI). → 사용자 결정 1
4. **메신저는 활용하되 의존하지 않는다.** 알려야 할 일은 메신저와 별개로 알림함에 남고, 메신저가 없어도(`none`) 화면만으로 모든 기능을 쓴다. → `CLAUDE.md` 알림함 절
5. **전환 중에도 매 단계 끝에서 서버에 올릴 수 있는 상태를 유지한다.** 화면 SPA 전환은 맨 마지막이다. → [01 §2.1](./01-requirements.md#21-phase-구분)
6. **비밀값(토큰·계정·주소)은 저장소와 문서에 쓰지 않는다.** `.env`와 환경변수 이름만 쓴다.
